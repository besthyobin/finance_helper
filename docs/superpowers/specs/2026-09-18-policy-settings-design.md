# 매매 정책 조회 및 실시간 손절 설정 기능 설계

작성일: 2026-09-18
목표: 모의투자 웹 화면(UI)에서 현재 적용 중인 매매 전략 및 파라미터(손절, 익절, 시초 범위, 강제 청산 등) 정보를 확인하고, 손절 수치(`stop_pct`) 등을 직접 변경하여 실시간 모의투자에 즉시 반영할 수 있도록 한다.

---

## 1. 요구사항 및 배경

### 배경
- 현재 모의투자(`paper.py`)는 ORB(Opening Range Breakout) 전략을 고정 파라미터(손절 -1.0%, 익절 +2.0%, 범위 09:30, 청산 15:15)로 실행 중임.
- 사용자는 현재 어떤 매매 정책이 적용되고 있는지 화면에서 확인하기 어렵고, 장세 변화에 따라 손절 폭(예: -1.5%, -2.0% 또는 -0.5%)을 유연하게 조절하고 싶어 함.

### 핵심 요구사항
1. **매매 정책 조회**:
   - UI 상단에 현재 적용 중인 전략 정보(전략명, 시초 범위 돌파 기준, 손절률, 목표 익절률, 강제 청산 시각, 수수료/세금/슬리피지 비용 구조)를 명확히 표시.
2. **손절/익절 수치 변경**:
   - UI에서 손절률(`stop_pct`, 기본 -1.0%)과 목표 익절률(`target_pct`, 기본 +2.0%)을 직접 입력 및 수정 가능.
   - [저장 / 적용] 버튼을 누르면 유효성 검사 후 서버로 전송.
3. **실시간 모의투자 즉시 반영**:
   - 변경된 정책이 `policy.json`에 영속화되고, 실행 중인 모의투자 프로세스(`paper.py`)가 매분 루프에서 변경 사항을 감지하여 실시간 전략 인스턴스에 즉각 반영.

## 2. 시스템 아키텍처 및 데이터 흐름

```text
[웹 UI (브라우저)]
   │
   ├─ 1. GET /api/policy ────> 현재 정책 조회 및 폼 입력창에 바인딩
   │
   └─ 2. POST /api/policy ───> JSON 전송 {"stop_pct": -1.5, "target_pct": 2.5}
                                   │
                                   ▼
                            [web.py API 핸들러]
                                   │
                                   ▼
                         [trader/policy.json] <─── 변경 내용 저장 (원자적 파일 쓰기)
                                   │
                                   ▼
                        [paper.py 실시간 감지]
                                   │ (매분 또는 변경 시 reload)
                        [DayRunner & Strategy]
                                   │
                        runner.strategy.stop = -1.5%
                        runner.strategy.target = +2.5%
                        (다음 분봉 체결 판단에 즉시 적용)
```

## 3. 세부 설계

### (1) 매매 정책 파일 (`trader/policy.json`)
```json
{
  "strategy": "orb",
  "stop_pct": -1.0,
  "target_pct": 2.0,
  "range_end": "09:30",
  "exit_at": "15:15"
}
```

### (2) 정책 관리 모듈 (`trader/policy.py`)
- `DEFAULT_POLICY`: 기본 딕셔너리
- `load_policy(path) -> dict`: 파일이 없거나 오류 시 기본값 반환
- `save_policy(policy, path)`: 유효성 검사 후 임시 파일 거쳐 atomic write
- `validate_policy(policy)`:
  - `stop_pct`: -50.0 ~ -0.1 범위의 실수
  - `target_pct`: 0.1 ~ 100.0 범위의 실수
  - `range_end`, `exit_at`: HH:MM 형식

### (3) 백엔드 API (`trader/web.py`)
- `GET /api/policy`: 현재 정책 + 비용 구조(수수료, 세금, 슬리피지) 반환
- `POST /api/policy`: 요청 바디 파싱 및 검증 후 `policy.json` 저장

### (4) 모의투자 실시간 연동 (`trader/paper.py`)
- `Paper` 클래스에 `self.policy` 저장.
- 매 분 봉 처리 전 `self.sync_policy()` 호출:
  - `policy.json` 파일의 수정 시간(mtime) 또는 내용 변화 감지
  - 변경 시 `self.runners[symbol].strategy.stop` 및 `target` 갱신
  - 로그 기록: `log.info("매매 정책 변경 적용: 손절 %s%%, 익절 %s%%", stop, target)`

### (5) 프론트엔드 UI (`web/index.html`, `web/app.js`, `web/style.css`)
- 현재 상태 테이블 상단에 **'매매 정책 설정' 카드 섹션** 추가:
  - 전략: `ORB (시초가 범위 돌파)`
  - 기준: `09:00 ~ 09:30 고가 돌파 시 진입`
  - 강제 청산: `15:15`
  - 손절률 입력 필드 (`stop_pct`, 단위 `%`, 기본 `-1.0`)
  - 목표 익절률 입력 필드 (`target_pct`, 단위 `%`, 기본 `+2.0`)
  - [정책 적용] 버튼 및 실시간 상태 안내 배지

## 4. 엣지 케이스 및 위험 관리

1. **잘못된 입력값**:
   - 손절률이 양수(예: +1.0)로 입력된 경우 자동으로 음수로 보정하거나 400 에러 처리.
   - 숫자가 아닌 값 입력 시 클라이언트 및 서버 양쪽에서 유효성 검증.
2. **장중 손절 변경 시 기존 포지션**:
   - 이미 보유 중인 주식(예: SK하이닉스, 삼성전자)의 경우, 손절선이 변경되면 다음 분봉 종가 평가 시 새 손절선 기준으로 즉각 손절 여부를 판단합니다.
3. **마감 비교 일관성**:
   - 마감 비교 시 당일 최종 정책 파라미터를 사용하여 일일 백테스트를 수행합니다.
