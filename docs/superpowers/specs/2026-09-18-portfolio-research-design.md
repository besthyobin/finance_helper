# 포트폴리오 전략 연구 설계

- 작성일: 2026-09-18
- 관련: `docs/superpowers/specs/2026-09-18-swing-backtest-design.md` (일봉 스윙 백테스트), `docs/superpowers/specs/2026-09-17-daily-selector-design.md` (매일 종목 선정)
- 목표: 실제 투자로 이어질 만큼 보수적인 기준을 **미리 정하고**, 그 기준을 모두 넘는 전략이 있는지 판정한다. 통과하면 모의투자(최소 3개월) → 소액 실투자(10만 원) 순서로 간다. 이 문서는 1단계(전략 연구)만 다룬다.

## 1. 배경

- 당일 청산 orb: 비용(거래당 약 0.33%)을 넣으면 80개 파라미터 조합 모두 손실
- 일봉 스윙 `breakout_trend`: "오늘의 거래대금 상위 100"으로는 검증 구간 거래당 +16.2%였으나, 분할일 시점 상위 100(현재 상장 전 종목 2,600개에서 선정)으로 다시 돌리면 거래당 +1.4%, 3년 누적 +7.5%로 같은 종목 단순 보유(+47%)에 크게 못 미쳤다. 차이의 대부분이 종목 선정 편향이었다
- 결론: 결과를 보고 판단하지 않고, 통과 기준을 먼저 정한 뒤 편향 없는 조건에서 포트폴리오 단위로 검증한다

### 실측 (2026-09-18)

- `GET /api/v1/stocks/all?market=KOSPI|KOSDAQ&securityType=STOCK&commonShare=true`: 현재 상장 보통주 KOSPI 803, KOSDAQ 1,797. `status=DELISTED`는 0건 → 상장폐지 종목 데이터는 받을 수 없다(남는 생존 편향)
- 수정주가 일봉은 1995년까지 받을 수 있다(종목당 10년 약 13페이지)
- 서버 `postgresql.conf`에 `shared_preload_libraries = 'timescaledb'`, 확장 2.15.2가 `trader`·`trader_test`에 생성됨. `minute_bars`·`daily_bars` 하이퍼테이블 전환 코드는 main에 합쳐졌고 운영 DB 적용은 대기 중

### 확정된 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 진행 방식 | 통과 기준을 먼저 정하고, 모두 넘을 때만 다음 단계 | 사용자 요구: 실제 투자로 이어질 만큼 보수적·안정적 |
| 대상 종목 | 매월 첫 거래일, 전날까지 250거래일 거래대금 상위 100 보통주(250거래일 이상 데이터 있는 종목) | 그 시점에 알 수 있던 정보만 사용 |
| 데이터 | 현재 상장 보통주 전체 + KODEX 200(069500) 10년치 수정주가 일봉 | 월별 대상 종목 계산에 전체 종목 필요 |
| 자금 | 판정은 10만 원, 참고로 1,000만 원도 계산. 정수 주, 동시 보유 N=3·5 | 실투자 금액 기준 판정 |
| 후보 전략 | A 추세 돌파 + 시장 필터, B 월간 모멘텀 + 시장 필터 | 사용자 선택. 후보 수를 제한해 우연한 통과를 줄임 |
| 비교 기준 | KODEX 200 보유, KODEX 200 매월 정기 매수 | 지수를 사는 것보다 못하면 의미 없음 |
| 조합 선택 | 개발 구간(2016-09-18 ~ 2023-09-17) 샤프 비율 최고 조합 하나를 전략마다 고르고, 검증 구간(2023-09-18 ~ 2026-09-17)은 그 조합만 1회 | 과최적화 차단 |
| 계산 형식 | 연구 시뮬레이션은 `float`, 운영 코드는 기존 `Decimal` 유지 | 수백 종목 × 10년 속도 |

## 2. 통과 기준 (사용자 확정)

| 기준 | 판정 방법 |
|---|---|
| 종목 선정 | 월별 그 시점 정보만 사용 (시뮬레이션 방식으로 보장) |
| 검증 수익 | 검증 CAGR > 0 이고 개발 CAGR의 50% 이상 |
| 시장 대비 | 검증 샤프가 KODEX 200 보유·정기 매수 샤프보다 모두 높음 |
| 최대 낙폭 | 개발·검증 모두 MDD 20% 이내 |
| 연도별 안정성 | 10년 전체 연속 실행에서 완전한 달력 연도 중 70% 이상 수익 플러스 |
| 거래 수 | 검증 구간 거래(청산 완료 기준) 100건 이상 |
| 자금 제약 | 10만 원·정수 주·동시 보유 N 조건으로 계산 (시뮬레이션 방식으로 보장) |

판정표의 모든 항목이 통과면 "모의투자 진행 가능", 하나라도 불합격이면 "불합격"과 불합격 항목을 표시한다. 통과 전략이 없으면 결과와 대안(지수 ETF 정기 매수 등)을 사용자에게 보고한다.

## 3. 범위

**포함**
- 전체 종목 일봉 수집(`research.py --collect`)
- 월별 대상 종목 쿼리
- 포트폴리오 시뮬레이터(현금·정수 주·동시 보유 제한·다음 날 시가 체결·비용·시장 필터)
- 전략 A·B, 비교 기준 2개
- 지표·판정표·보고서 출력(화면 + `trader/reports/research-YYYY-MM-DD.md`, git 제외)
- 하이퍼테이블 운영 전환(수집 전)

**제외**
- 모의투자·선정기 연동(통과 후 별도 설계)
- 실주문
- 추가 전략(평균회귀, 저변동성 등)
- 상장폐지 종목 데이터(받을 수 없음, 보고서에 한계로 명시)

### 4.1 데이터와 대상 종목 (`universe.py`, `toss.stocks_all`)

- `TossClient.stocks_all(market)`: `GET /api/v1/stocks/all?market=&securityType=STOCK&commonShare=true` → `[symbol]`
- 수집: 전체 보통주 + `069500`을 `fetch_daily_history(symbol, 오늘 − 10년)` → `store.save_daily_bars`. 종목별 실패는 로그 후 계속, 인증 오류는 중단. 기존 `swing_backtest.collect`를 재사용한다
- `month_starts(conn, date_from, date_to)`: `daily_bars`의 069500 거래일 중 매월 첫 거래일 목록
- `monthly_universe(conn, dates, size=100, lookback=250)`: 각 날짜 d에 대해 d 전날까지 최근 250거래일 `close × volume` 합 상위 `size` 종목(250거래일 미만 종목 제외, 069500 제외). SQL 윈도 함수로 DB에서 계산해 `{d: [symbol 순위순]}` 반환

### 4.2 포트폴리오 시뮬레이터 (`portfolio.py`)

- 입력: 날짜순 거래일 목록, 종목별 일봉(`{symbol: {date: (open, high, low, close, volume)}}`, float), 월별 대상 종목, 시장 지표(069500 종가), 전략 객체, 시작 자금, 동시 보유 N, 비용
- 하루 처리 순서:
  1. 전날 결정한 주문을 오늘 시가로 체결한다. 매도 먼저, 그다음 매수(순위순)
     - 매수 수량 = `floor(min(주문 시점 평가액 ÷ N, 현금) ÷ (시가 × (1 + 슬리피지)) )`. 0이면 건너뜀. 보유 수가 N이면 건너뜀
     - 오늘 시가가 없는 종목(거래정지 등)의 주문은 취소
  2. 오늘 종가로 평가액을 기록한다(종가가 없는 보유 종목은 마지막 종가)
  3. 전략이 오늘 종가까지의 정보로 내일 주문(매도 목록, 순위 있는 매수 목록)을 낸다
- 시장 필터: 069500 종가가 200일 평균 미만이면 전략의 매수 목록을 비운다(매도는 그대로)
- 기간 끝에 남은 보유는 마지막 종가로 평가만 한다(청산 거래로 세지 않음)
- 거래 기록: 청산 완료 거래마다 (종목, 진입일, 청산일, 수익률%, 원화 손익)
- 비용: 수수료 0.00015(양쪽), 매도세 0.002, 슬리피지 0.0005(양쪽)

**전략 A `TrendBreakout(entry, trend, exit)`**
- 매수 후보: 오늘 대상 종목 중 미보유이고 `swing.BreakoutTrend`와 같은 규칙(오늘 종가 > 직전 entry일 최고 종가, 오늘 종가 > trend일 평균)을 만족하는 종목. 순위는 대상 종목 순위
- 매도: 보유 종목 중 오늘 종가 < 직전 exit일 최저 종가(대상에서 빠져도 적용)
- 조합: (20,50,20), (20,100,20), (55,50,20), (55,100,20)

**전략 B `MonthlyMomentum(months, n)`**
- 매월 첫 거래일 종가 기준, 그날 대상 종목의 최근 `months`개월(21거래일 × months) 수익률 상위 `n`개가 목표
- 목표에 없는 보유는 매도, 목표 중 미보유는 매수(순위 = 모멘텀 순위). 월초가 아니면 주문 없음
- 시장 필터가 꺼져 있으면 매수만 비운다(목표에서 빠진 종목 매도는 그대로)
- 조합: months 6·12 × n 3·5 (B의 동시 보유 N은 n과 같다)

**비교 기준**
- KODEX 200 보유: 첫 거래일 시가에 전액(정수 주) 매수 후 보유
- KODEX 200 정기 매수: 시작 자금을 구간 개월 수로 나눈 같은 금액을 매월 첫 거래일 시가에 정수 주로 매수하고, 쓰지 못한 돈은 현금으로 둔다

### 4.3 지표·판정 (`metrics.py`)

- `summarize(equity_by_date, trades)`: CAGR, 연간 변동성(일간 수익률 표준편차 × √252), 샤프(CAGR ÷ 변동성, 무위험 0), MDD, 달력 연도별 수익률(완전한 연도만), 거래 수, 승률, 평균 보유일
- `verdict(dev, val, val_benchmarks, full_years, capital)`: 2절 기준마다 (이름, 값, 기준, 통과 여부)와 종합 판정

### 4.4 연구 실행기 (`research.py`)

```
research.py --collect      # 전체 보통주 + 069500 10년치 일봉 수집
research.py                # 실험 실행, 보고서 출력·저장
```

- 실험 순서: 월별 대상 종목 계산 → 전략별 조합을 개발 구간(10만 원, A는 N=3·5 각각)으로 실행 → 전략마다 샤프 최고 조합 선택 → 검증 구간 실행(10만 원 판정, 1,000만 원 참고) → 10년 연속 실행으로 연도별 수익률 → 판정표
- 보고서: 조합별 개발 표, 선택 조합, 검증 표(비교 기준 포함), 판정표, 연도별 수익률, 한계(상장폐지 종목 없음, 수정주가 기준, 호가·체결량 무시)

## 7. 운영 순서

1. 장 마감 후(15:31 ~ 20:30) 운영 DB에 하이퍼테이블 전환 적용(백업 → `schema.sql` → 행 수 확인 → 압축 확인)
